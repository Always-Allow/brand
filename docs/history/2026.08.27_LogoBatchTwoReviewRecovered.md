## Codex CLI, 15 findings

### Already answered by `4a4109c`

- **1 (High)** `LogoExport --check` had no structural assertion. It now checks that references
  resolve, and that there is no live text, no embedded raster, no empty glyph wrapper, no retired
  colour, and a plausible path count.
- **9 (Medium)** "Every SVG here is dimensionless" was false. `Wordmark.svg` no longer carries
  width or height, and the matrix now carves out `WordmarkSource.svg` explicitly.
- **11 (Medium)** The QR disposition conflicted with the guide. Overtaken by her instruction the
  same day to delete all four; the matrix records that they are not being remade and that a
  reusable template is a possible future asset. **Note for the next session: this is her
  overriding the guide, which requires all four regenerated. The guide has not been amended.**
- **7 (High)**, partly. The symbols now have a builder. The rest of this finding is still open, below.

### Still open, verifier weaknesses

- **2 (Medium)** `WordmarkBuild` does not assert that path data is identical to the source. A
  same-length path mutation passes. Fix: compare every `d` string against the source.
- **3 (High)** `LockupBuild.verify()` checks the computed object, not the serialized output. A
  template error could place or scale the artwork wrongly while every check passes. It also does
  not confirm the whole source artwork was carried through. **This is the most valuable one on the
  list.**
- **4 (High)** `AvatarBuild` does not read tile geometry, transform or crop clearance back from the
  output; the clearance is recomputed from constants. A wrong emitted translate, scale, corner
  radius or tile size passes.
- **5 (High)** `BannerBuild` still has no `--check` mode, writes before validating, and does not
  await `document.fonts.ready`. The font hash pin added in `4a4109c` covers font identity, so the
  live gaps are the missing check mode, the write-before-validate order, and the fonts-ready wait.
- **6 (High)** `RasterExport` validates after writing and has no manifest tying the nine PNGs to
  their sources. Chrome version drift would pass silently.
- **7 (High)** The matrix's opening claim, that every asset is script generated and every script
  verifies before writing, is still not true: the small mark is hand authored (hash pinned), and
  the banner and raster scripts validate after writing.

### Still open, compliance and accuracy

- **10 (High)** `SymbolBone.svg` is described as "for dark grounds", while the guide says "No dark
  treatments anywhere, on any surface". Her open ruling about keeping historical dark files does
  not authorise a NEW dark-ground asset. **Needs her decision. Same class as the dark master
  question.**
- **12 (Medium)** All nine PNG filenames and both font filenames use hyphens before their size or
  between sections, e.g. `2026.08.27_Avatar-500.png`. The locked convention is underscores, with an
  invoice ID as the only documented exception. Verified still true.
- **13 (High)** `WordmarkBuild.mjs` contradicts itself: line 3 says there is no font file, line 23
  says the face is DM Serif Display and the font is in the repository. Verified still true. Line 3
  is the stale half and should go.
- **15 (Medium)** `LogoExport.mjs` line 13 still tells the reader to raster through `qlmanage`,
  which the matrix explicitly prohibits because it pads non-square art into a square and flattens
  transparency. Verified still true. It should point at `RasterExport.mjs`.
- **8 (Medium)** `WordmarkSource.svg` carries the retired colour eleven times. Recorded as
  deliberate, and Codex reads the retired-colour rule as absolute. **A judgement call for her or
  the next session: keep the historical source as it is, or strip the file entirely.**

### Not defects, packet gaps

- **13, in part** and **14 (Medium)** Codex could not inspect the font binaries or verify the
  deletion claims, because neither the `fonts/` directory nor the base tree was in the packet.
  Those claims were verified in the repository directly (a repo-wide reference search, and a
  sha256 comparison of every root file against every kit file). **Fix the packet next time:**
  include `brand/fonts/`, and either give the reviewer the worktree or pre-compute the evidence.

## Addendum, 2026-08-27 evening: what has since been fixed

The list above was written before any fixes. Some are now done, in commit `223f848` on
`visual-lane-5`. This addendum is appended rather than edited into the list, so the record of
what the reviewers actually said stays intact.

Fixed:

- **Codex 3**, the lockup verifier. `verify()` now parses the markup it emitted and re-derives
  the scale, the gap, the centring and the box from the attributes actually written. It caught a
  real thing while being written: re-deriving both axis scales from six-decimal attributes puts
  about 1.3e-8 of rounding between them, so the uniform-scale test is now proportional rather
  than absolute.
- **Codex 5**, the banner, in the two parts that mattered. It has a `--check` mode, and it
  renders to a temporary file and validates before anything reaches the committed path.
  **Not done:** it still does not await `document.fonts.ready`. Font identity is covered by the
  hash pin, so this is a timing risk rather than an identity one.
- **Codex 7**, the matrix's opening claim. It now states the two real exceptions instead of
  claiming they do not exist: the small mark is hand authored and hash pinned, and
  `RasterExport.mjs` still validates after writing.
- **Codex 13**, `WordmarkBuild.mjs` line 3, the stale "no font file in the repository".
- **Codex 15**, `LogoExport.mjs` line 13, which still sent the reader to `qlmanage`.

Still open, unchanged:

- **Codex 2**, `WordmarkBuild` does not compare path data against the source.
- **Codex 4**, `AvatarBuild` does not read tile geometry back from its output.
- **Codex 6**, `RasterExport` validates after writing and has no source-to-output manifest.
- **Codex 12**, the filename hyphens. Worth knowing: this session ADDED to it rather than fixing
  it. `2026.08.27_LogoMarkTiny-16.png`, `2026.08.27_Lockup-747x103.png` and
  `2026.08.27_LogoMaster-1054x840.png` all use a hyphen before the size, matching the existing
  set. That was a deliberate choice to keep one convention across the folder rather than leave it
  half converted, but it does mean the rename job is now eleven files plus three.
- **Codex 8 and 10**, both of which need Sarah and neither of which she has been asked yet.

Not from this review, but fixed in the same commit, from the design-lens workflow over the
rendered assets: the master clipped its own ground shadow, the lockup's box held artwork at 53.5%
